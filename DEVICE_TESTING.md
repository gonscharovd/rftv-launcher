### Диагностические метрики Debug

Собирать только Debug-логи:

```bash
adb logcat -c
# выполнить несколько открытий каталога и Control Center
adb logcat -d -s RFTV_PERF
```

Формат стабильный, одна запись — одна строка с ключами `key=value`:

- `event=opening`: `overlay`, `open_count`, Java и native heap до снимка.
- `event=opened`: `open_to_visible_ms`, `capture_ms`, размеры исходного снимка, его размер в байтах, Java и native heap до/после открытия.
- `event=blur_complete`: `blur_ms`, размер уменьшенного bitmap, размер размытого bitmap и `success`.

`overlay` принимает `app_catalog` или `control_center`. `open_count` — возрастающий счётчик открытий в пределах жизни процесса. Все размеры указаны в байтах, разрешения — в пикселях, время — в миллисекундах. `capture_ms` измеряет создание полноразмерного снимка до уменьшения; `blur_ms` измеряет уменьшение и генерацию blur на фоновом executor. Отсутствие строки `event=blur_complete` при закрытии overlay до окончания фоновой задачи не означает зависание: результат устаревшего поколения отбрасывается.

## 10. Приоритет TV Manager

TV Manager не является частью ближайшей разработки лаунчера. На физическом ТВ пока допускается только read-only осмотр. Не отключать пакеты в рамках текущей приёмки. Проверка Shizuku и любые операции с пакетами отложены до отдельного согласованного этапа.


## Проверка v0.9.1 с телефона и ТВ

Эта проверка не требует ПК, ADB или подключения к разработческому окружению. Она выполняется после публикации v0.9.1 через встроенный OTA-апдейтер.

### OTA-обновление

- [ ] На ТВ открыть **Настройки RFTV → О системе → Обновления**.
- [ ] Убедиться, что текущая версия указана как 0.9.3 (если обновление ещё не установлено).
- [ ] Нажать **Скачать и установить обновление**.
- [ ] Дождаться загрузки и автоматических проверок; при запросе Android разрешить установку приложений для RFTV и вернуться в лаунчер.
- [ ] В штатном установщике Android подтвердить обновление RFTV Launcher.
- [ ] После установки открыть **Настройки RFTV → О системе** и проверить версию 0.9.1.
- [ ] Убедиться, что избранное, порядок Dock, обои, тема и остальные настройки сохранились.
- [ ] Если OTA сообщает об ошибке SHA-256, package name, versionCode или сертификата, не пытаться обходить проверку; сфотографировать полный текст ошибки.

### Экран диагностики

- [ ] Открыть **Настройки RFTV → Диагностика → Открыть диагностику**.
- [ ] Проверить версию/versionCode, модель, Android/API, ABI и memoryClass.
- [ ] Вернуться на Home, открыть каталог приложений, закрыть его; затем открыть и закрыть Control Center.
- [ ] Снова открыть экран диагностики: вверху списка должны появиться оба типа открытий, время capture/blur/показа, размеры bitmap и Java/native heap до/после.
- [ ] Повторно открыть каталог и Control Center: тип открытия должен стать «повторное» для каждого типа после первого открытия в текущем процессе. Очистка истории удаляет записи, но не сбрасывает классификацию холодного/повторного открытия и общий счётчик до перезапуска процесса.
- [ ] Нажать **Очистить историю диагностики**, убедиться, что история очищена; открыть оверлеи снова и проверить появление новых записей.

### Что сфотографировать телефоном

1. Экран **О системе** с версией 0.9.1.
2. Верхнюю часть **Диагностики** с моделью устройства, Android, ABI и memoryClass.
3. Записи диагностики каталога и Control Center (при необходимости несколько фотографий, прокручивая экран).
4. Если OTA не устанавливается — экран с полным сообщением об ошибке.

Фотографировать экран ТВ целиком, чтобы были видны заголовок раздела и значения. ADB, компьютер и ручная передача файлов не нужны.
