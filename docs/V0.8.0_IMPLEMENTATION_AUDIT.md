## 2. Обои: диагностика и проверка URL

Загрузчик использует раздельные файлы для preview и full image. Перед сетевым запросом пытается декодировать локальный файл; повреждённый файл удаляется и загружается заново. Скачивание идёт во временный файл с последующим атомарным переименованием. Проверяются HTTP 2xx, Content-Type image/*, непустой ответ, максимальный размер и успешный Bitmap decode. При ошибке выбранного изображения пробуется следующая фотография; успешный fallback сохраняется в настройках. Ошибка записывается в `wallpaper_last_error` и Logcat tag `RFTVWallpaper`.

Добавлен `scripts/check_wallpaper_urls.py`. Скрипт извлекает все 20 Unsplash URL из MainActivity, проходит redirect, проверяет HTTP status, MIME type, размер и полное декодирование Pillow.

**Подтверждённый запуск:** GitHub Actions run [42616040741](https://github.com/gonscharovd/rftv-launcher/actions/runs/42616040741), commit `8f05508058ca29bf55dbc8714290e3457c5d8e6c): 20/20 URL вернули HTTP 200 и `image/jpeg`; все изображения декодированы как JPEG 1920×1080. Размеры ответов — примерно 172 KB–883 KB. URL-список с этого запуска не менялся; окончательный PR HEAD должен повторно пройти тот же CI step.

Эта проверка подтверждает доступность изображений из GitHub Actions, но не доказывает, что StarOS/провайдер сети на телевизоре успешно скачивает и показывает их.

## 3. Liquid Glass и Control Center

Для Android 9/API 28 используется собственный downsampled snapshot blur: bitmap уменьшается, box blur выполняется в worker executor и результат кэшируется по ключу выбранных обоев. Blur не запускается на каждом кадре. Один и тот же результат используется в стеклянном Home hero и под overlay surfaces. На более новых API нативный путь может быть добавлен отдельно, но текущий минимальный API не зависит от RenderEffect.

Control Center строится справа, с полным доступным вертикальным размером, glass gradient/stroke, отдельными vector-иконками, группировкой и явной таблицей переходов фокуса. При закрытии сначала возвращается фокус на исходный элемент; если он больше не виден, используется кнопка Control Center.

Пользователь подтвердил, что tvOS Launcher с blur плавно работает на целевом телевизоре. Поэтому blur не исключается по предположению о слабом GPU. Производительность и артефакты необходимо измерить физически.

## 4. Заставка и данные

Ручная `ScreensaverActivity` и системный `RftvDreamService` используют общий `ScreensaverDashboardRepository`:

- Open-Meteo — текущая погода для Челябинска;
- ЦБ РФ — USD/EUR;
- RSS — РИА Новости и Google News World.
- Четыре источника запрашиваются параллельно отдельными Future.
- Connect/read timeout — 8 секунд; общий timeout ожидания каждой задачи — 14 секунд; ответ ограничен 2 MB.
- Свежесть кэша хранится отдельно для погоды, валют, российской и международной ленты.
- При ошибке источник не затирает последнее успешное значение и его timestamp.
- Отмена Future при pause/stop прерывает ожидание и отменяет сетевые Future; сетевые соединения дополнительно ограничены timeout.
- `ScreensaverSession` не допускает одновременный показ ручной Activity и DreamService в одном процессе.

Ограничение: город и RSS endpoints заданы в коде; пользовательский выбор города/источников не добавлялся. Системная заставка доступна только если прошивка показывает DreamService в настройках.

## 5. Донорский аудит и лицензии

### tvOS Launcher

Источник: https://github.com/techgenius1/tvOS-Launcher  
Лицензия: Apache License 2.0; в репозитории также есть NOTICE с авторством и перечнем third-party components.

Изучены исходники Control Panel, blur helper и навигации Settings. Подтверждены архитектурные идеи snapshot/downsample/box blur, группировка панели и управление focus stack. RFTV реализует собственный Android Views код; исходный код и графические ресурсы tvOS Launcher в этот этап не копируются. Если в будущем будет перенесён конкретный код, необходимо сохранить Apache LICENSE/NOTICE и добавить атрибуцию.

### CleanYourTV

Источник: https://github.com/Gathin23/cleanyourtv  
Лицензия репозитория: MIT; отдельные шрифты/ресурсы имеют собственные лицензии. Уведомление об адаптированных package reference data уже находится в `THIRD_PARTY_NOTICES.md`.

Изучены AppAdapter, AppLibraryDialog, DockSlots, GridNavigation и GlassView. Полезные идеи: single-row dock, адаптивная ширина плиток, отдельный App Library, сохранение идентичности приложений и устойчивого focus. ## 7. Что обязательно проверить физически

Устройство: Sber SDX-50U4123B, StarOS 1.103.91, Android 9/API 28, ARMv7, MediaTek MT9632.

1. Установить только стабильный подписанный Release через OTA; убедиться, что настройки и избранное сохранены.
2. Проверить показ фотографий после cold start, выбор всех наборов день/ночь, авто-режим, смену обоев, кэш и офлайн.
3. Проверить Home clocks/weather, погодный overlay и пять дней прогноза.
4. Проверить адаптивный Dock, каталог, длинный список приложений, запуск, скрытие/возврат и обновление после установки/удаления.
5. Проверить Control Center: открытие справа, blur, иконки, каждое действие, DPAD, Back и возврат фокуса.
6. Проверить Settings: Left/Right, Up/Down, прокрутку, выбранный раздел, Back и отсутствие потери фокуса.
7. Проверить ручную и системную заставку, интервал таймера, выход любой кнопкой, отсутствие дублей, часы, курсы, погоду и обе RSS-колонки.
8. Проверить длительную работу, память, плавность blur и восстановление после пропадания сети.

Физическая приёмка v0.8.0 пока **не выполнена**. Ни один из этих пунктов не считается пройденным до подтверждения владельца.
