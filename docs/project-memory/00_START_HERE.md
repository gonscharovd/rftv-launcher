## Быстрый профиль проекта

RFTV Launcher — нативный Kotlin Android TV launcher с эстетикой tvOS/Liquid Glass. Основная целевая платформа разработки: Sber SDX-50U4123B / Salute TV StarOS, Android 9/API 28, MediaTek MT9632, ARMv7. На проверенной базе опубликован stable Release v0.3.0 (versionCode 3). Физическая приёмка на телевизоре не подтверждена.

## Инструкция новому ИИ

1. Прочитайте этот файл и перечисленные документы.
2. Получите актуальные сведения из GitHub: default branch, HEAD, ветки, PR, последние commits, workflow runs, latest stable Release и дерево файлов.
3. Сверьте документы с кодом. Не считайте статус из старого handoff текущим без проверки.
4. Осмотрите относящиеся к задаче исходники и историю коммитов до редактирования. Не выводите устройство реализации из названия файла.
5. Сохраните пользовательские изменения. Работайте в отдельной feature-ветке и используйте PR как штатный способ интеграции.
6. У ИИ полная техническая и операционная автономность в рамках доступных прав: анализ, реализация согласованного объёма, рефакторинг, архитектурные решения, тестирование, GitHub Actions, создание/обновление/слияние PR и публикация проверенных stable Release выполняются самостоятельно.
7. Единственный продуктовый gate: до добавления новой пользовательской функции, нового раздела/сценария или изменения концепции получи согласование Product Owner. Исправления, оптимизация, совместимость, завершение уже утверждённых задач, внутренние архитектурные изменения и документация не требуют отдельного согласования.
8. После каждого логического изменения обновите только релевантные документы, а перед передачей обязательно `03_CURRENT_STATE.md`, `05_TASKS.md`, `10_SESSION_HANDOFF.md`.
9. Запустите доступные тесты и CI. Чётко отделяйте локальные проверки, CI, проверку подписанного APK и физическое тестирование.
10. Не публикуйте непроверенный APK. Signing key постоянный; не заменяйте, не экспортируйте и не раскрывайте его.
11. Самостоятельно доводите PR до merge и проверенный Release до публикации после прохождения всех release gates. Дополнительное разрешение Product Owner на merge/Release не требуется.

## Источники проекта

Материалы Library /Прошивка относятся к отдельному репозиторию gonscharovd/tvOS (testOS/tvOS Launcher), CleanYourTV и исследованию прошивки/аудиотракта Sber TV. Это не текущая реализация RFTV, не его backlog, не product specification и не подтверждение того, какой launcher/APK сейчас установлен на ТВ. Не переносить оттуда списки пользовательских приложений, функции, package actions, версии, signing state или рабочие ограничения как требования RFTV. Использовать только проверяемые технические факты об устройстве/OEM и конкретные донорские решения, если они помогают уже согласованной задаче RFTV. Инструкции read-only режима относятся к отдельному firmware/audio исследованию и не являются правилами автономности RFTV.

Сначала используйте [README](../../README.md), [ROADMAP](../../ROADMAP.md), [CHANGELOG](../../CHANGELOG.md), [DEVICE_TESTING](../../DEVICE_TESTING.md), [TV_MANAGER](../../TV_MANAGER.md), [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md), [WALLPAPER_CREDITS](../../WALLPAPER_CREDITS.md), исходники и workflows. Эти файлы остаются полезными первичными документами; данная память создаёт навигационный и управленческий слой, а не заменяет их.

**Важно:** состояние CI и релиза в документах — снимок на дату сверки. Перед любой новой публикацией самостоятельно перепроверьте актуальное состояние GitHub и все release gates.
